# Security reports

Do not publish credentials, private keys, personal network configuration or a used phone image in a public issue.

For a sensitive finding, use GitHub's private vulnerability reporting if the repository offers it. If it is unavailable, open an issue containing only a request for a private reporting channel; do not include exploit details or sensitive data there.

Reports should identify the affected revision, prerequisites, trust boundary, impact and minimal reproduction. A passing host test or an incomplete review is not evidence that the phone or installer is secure. The project has no supported production release and currently offers no security-support guarantee.
